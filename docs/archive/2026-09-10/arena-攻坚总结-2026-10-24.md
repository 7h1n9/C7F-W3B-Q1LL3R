## 二、核心改进：候选机制（banner 家族）

### 2.1 问题起源

靶场对每道题按实例发放 flag，但**靶机自己打印的 banner 往往才是正确答案**，
而平台声明的是 `CTF2{...}`。系统早期只试声明的 banner，导致真实答案被丢弃。

典型证据（run `de9ab053`）：`flag_candidates` 表里躺着 `n1book{afr_1_solved}`，
但实际只提交了系统自己套的 `CTF2{afr_1_solved}`，平台判 rejected。

### 2.2 最终方案

`_load_candidates()`（`backend/app/services/arena_solve.py`）现在按以下顺序展开：

1. **靶机原生值原样提交**（完整保留它自己的 banner）
2. 裸值套**题目声明的** banner（从 `flag_pattern` 解析）
3. 裸值套**常见家族**：`flag` / `n1book` / `CTF2` / `hitcon`

配套 `MAX_SUBMISSIONS_PER_RUN = 5` 上限，防止「候选数 × banner 数」爆炸触发平台限流。

### 2.3 排序的实证依据

排序不是猜的。每次 accepted 前都有一次 rejected 记录，1 秒内切换：

```
SQL注入-2   CTF2{login_sqli_is_nice}    rejected  00:47:27
SQL注入-2   n1book{login_sqli_is_nice}  accepted  00:47:28
```

**靶机 banner 排第一，是因为它被证明有效。**

### 2.4 六次翻盘（候选机制的真实战功）

| 题目 | 先失败 | 后成功 |
|---|---|---|
| `afr_1` | `CTF2{afr_1_solved}` | `n1book{afr_1_solved}` |
| `粗心的小李` | `CTF2{git_looks_s0_easyfun}` | `n1book{git_looks_s0_easyfun}` |
| `SQL注入-1` | `CTF2{union_select_is_so_cool}` | `n1book{union_select_is_so_cool}` |
| `SQL注入-2` | `CTF2{login_sqli_is_nice}` | `n1book{login_sqli_is_nice}` |
| `泄漏的秘密` | `CTF2{r0bots_...}` | `flag{r0bots_...}` |
| `ErrorFlask` | `CTF2{Y0u_@re_...}` | `flag{Y0u_@re_...}` |

出现的 banner 家族：`n1book` × 4、`flag` × 2，**没有一次是 `CTF2`**。

### 2.5 一个需要纠正的判断

`[极客大挑战 2019]HardSQL` 曾出现：

```
flag{ca646210-9f5e-4e98-b166-c5afb6a032bf}  rejected
CTF2{732569b0-ab67-4fca-91b7-125620b55e48}  accepted
```

这看起来像反例（`CTF2` 赢了），但**不是**：两个值内部的 UUID 完全不同。
平台每轮重新发 flag，所以这是「重跑换值」，与 banner 无关。
判据是内层值是否相同，不能只看外层。

## 三、知识库沉淀

### 3.1 新增条目（2 条，语料共 170 条）

**① `derived-filename-argument-provenance`**
适用：上传路径由函数计算得出。

核心：读清参数**是什么**。`md5($file['name'])` 哈希的是**客户端提交的文件名字符串**，
不是文件内容、不是 `tmp_name`。算对后先 GET 一次确认，404 就回去重读那行，不要排列组合猜盐。

**② `php-serialize-length-shift-via-filter-keyword`**
适用：先校验、后过滤，且过滤会把关键词改长。

这是 `piapiapia` 的真实卡点（连败 3 轮后靠此条目解出）：

```php
// update.php 用原始 POST 校验：只允许 [a-zA-Z0-9_]，最长 10
if(preg_match('/[^a-zA-Z0-9_]/', $_POST['nickname']) || strlen(...) > 10) die('Invalid nickname');

// class.php::mysql::filter() 之后改写整个序列化串
preg_replace('/select|insert|update|delete|where/i', 'hacker', $string);
```

`where`(5) → `hacker`(6)，**每处 +1 字节**。
昵称写 `wherewhere`（10 字符纯字母，通过校验）→ 过滤后变 `hackerhacker`（12 字符）
→ **长度差 2**，正好错位覆盖 `photo` 字段。

关键点：**注入片段要放 photo 的文件名里，昵称只负责制造长度差。**
此前一直把整个 `";}s:5:"photo"...` 塞进昵称，被字符类拒绝（试了 23/24/25/26/41/84 各种长度全废）。

### 3.2 语料字段的语义陷阱

`published_at` 是**技术的公开日期**，不是条目写入日期。
我曾填当天日期，被测试拦下（断言 `< 2025-01-01`）——这个字段用于回答
「该技术在某题出现时是否存在」，填未来日期会让语料自相矛盾。

## 四、工程教训

### 4.1 无人值守脚本的七个坑

写 `.probe/overnight_runner.py` 时踩到的，每个都曾让整夜空转：

| # | 坑 | 症状 | 修法 |
|---|---|---|---|
| 1 | `enqueue-ids` 对已存在的题返回 `skipped` | 20 秒就「完成」，其实是读到上一轮旧状态 | 必须 `bulk retry` 重置并确认 PENDING |
| 2 | 未确认 Run 真的启动 | 静默失败后空等到窗口结束 | 3 分钟内必须看到 `RUNNING`，否则判失败 |
| 3 | 单题窗口 16 分钟 | 砍掉 16.4 分钟才收尾的健康 Run | 放宽到 24 分钟 |
| 4 | 平台 `503 MAINTENANCE_MODE` | 被当成题目失败 | 读 `retryable` 字段，退避重试 |
| 5 | `MISSING` 算作系统故障 | 3 个已下架题导致整夜停机 | 只对 `UNKNOWN`/`CRASH`/`BACKEND_DOWN` 计数 |
| 6 | 多 practice_ground | `SQL注入-2` 报「无法回到 PENDING」 | 用题目自己的 `practice_ground_id` 入队 |
| 7 | UTC 显示成 local | 看到 23:00 以为算错 | `--until` 按本地时区解析，显示时 `.astimezone()` |

第 6 条特别值得记：它伪装成「队列异常」，实际是参数错误——
`enqueue-ids` 给了错误的 ground 会静默不生效，不报错。

### 4.2 诊断顺序（我犯过的两个错）

两次把**现象**当成**根因**：

1. 看到几条空输出 → 误判「观测链路坏了」
   量化后发现 145 条 `tool_result` 里只有 1 条空
2. 误判 `piapiapia` 卡在「md5 算错对象」
   实际那步早已做对（`GET /upload/<md5>` 返回 200），真卡点是序列化长度错位

**正确顺序：读源码 → 构造最小验证 → 看真实返回 → 才怀疑能力。**

为此保留三个诊断脚本：

- `.probe/diag_chain.py` — 对比 facts（结论）与最后命令（行动）
- `.probe/diag_empty.py` — 量化 `tool_result` 空值率
- `.probe/diag_cmd.py` — 打印完整命令与输出

### 4.3 重跑的价值被低估

23 道新增里，**4 道是连败 2-4 轮后靠重跑突破**：

| 题目 | 突破轮次 |
|---|---|
| `piapiapia` | 第 4 次（加知识条目后） |
| `Hack World` | 第 3 次 |
| `BabyUpload` | 第 3 次 |
| `HardSQL` | 第 4 次 |

**翻盘率约 33%。** 单轮失败不能判定题目难度——引擎与模型波动是主要变量。
但也不能无限重跑：`Leaking` 7 轮全败，说明存在真硬卡点。

## 六、下一步建议

按优先级：

**P0** — `Leaking` 的 vm2 逃逸：需要新增一条技术条目，覆盖
`this.constructor.constructor('return process')()` 类原型链逃逸，
以及 12 字符限制下的分步构造。

**P1** — 候选机制已到位，但**只在 Run 结束且提取到候选时生效**。
若 Worker 完全没提取到值，机制无效。可考虑在收敛前主动提示 Worker「把看到的
任何 `xxx{...}` 形态字符串写入 fact」。

**P2** — 无人值守脚本已稳定（7 个坑全修），可考虑固化进 `scripts/` 而非 `.probe/`，
作为正式运维工具。

**P3** — `MAX_SUBMISSIONS_PER_RUN = 5` 是经验值，若后续出现更多 banner 家族可调，
但需同步观察限流（`RATE_LIMIT_EXCEEDED`）。
