## 四、对比：这批题之前跑不出来

这 27 道题在原队列里都尝试过，全部 UNSOLVED。改动前它们拿到的唯一指令是：

```
No recipe matched. Send the confirming exploit request within your first three

```

68 道题共用这一条。

改动后同一批题 75% 解出，且探针在命令序列前 24 条内必然出现。

## 五、必须诚实说明的保留

1. **暖场仍在**。多数 Run 的前 1-2 条命令仍是读 `SKILL.md` / `ls`。探针前置把「首次触靶」从「从来没打到」变成「第 2-24 条」，但没有做到「第 1 条」。上一轮把 FA 提到 prompt 最前的改动，效果弱于预期。
2. **解题率不能直接外推到全量**。这批题是「有 CVE + 语料命中」的子集，题本身可能是 Easy/Medium。不能用 75% 宣称整体能力提升。
3. **样本 12 道，偏小**。75% 的 95% 置信区间很宽（约 43%-95%），不足以做定量结论。
4. **失败 3 道的形态**要看，不能只报成功。

## 六、结论

**当初那个「信任门造成覆盖真空」的判断被证实了。** 不是模型不会做，是它在 68 道题上收到的是同一条无信息量的指令。

一个未实测配方的首行，即使换成「探针」这种低权威措辞，也足以把模型拉进正确的利用路径 —— 这就是从 1/81 覆盖到 27/81 的实际价值。

## 七、复盘后的两处探针质量修复

失败的两道不是思路问题，是探针本身有缺陷：

### 1. Jenkins：URL 被 190 字上限切断

探针原文 400+ 字符，被切成：

```
send `GET http://t/securityRealm/.../checkScript?sandbox=true&value=public class x
```

模型在第 5 条命令发出了这个**半截请求**，服务器返回 400，Run 在 #22 死亡。

**修法**：`_fa_payload_line()` 里，超长的 HTTP 请求**直接放弃下发**，而不是截断。理由：截断后的请求「语法合法、语义错误」，会让 Run 从我们自己的截断假象中学到「配方不适用」。放弃下发则回落到技法条款（一个决策过程），严格优于一个不可能成功的请求。

同时补上 URL 折行拼接：vulhub 把长 URL 断在 `?`/`&` 开头的行，之前只取第一行。

### 2. Drupal：下发了容器里不存在的脚本

探针是 `python3 drupa7-CVE-2018-7602.py -c "id" ...`，但该脚本属于配方，不在 Worker 镜像里。Run 前期命令全耗在 `No such file or directory`。

**修法**：`_FA_MISSING_SCRIPT` 拒绝「裸脚本名」形态（`python3 x.py` 无路径、无 `-c`/`-m` 前置）。绝对路径（`/home/kali/pocs/...`）和 `python3 -c "..."` 不受影响。

### 修复后的连带确认

收紧过滤后重测覆盖率，发现 UNSOLVED 从 81 掉到 57 —— **不是回归，是 24 道题被解出来了**（队列 SOLVED 49 → 60）。覆盖率数字下降完全由「题目离场」解释。

测试从 26 条增到 32 条，新增覆盖：裸脚本名拒绝、镜像内工具放行、超长请求放弃下发、URL 折行拼接。
