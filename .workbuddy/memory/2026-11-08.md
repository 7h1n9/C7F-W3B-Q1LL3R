## 自愈看门狗 `scripts/watch_unattended_run.sh`（已实测）

### 为什么必须做
夜间 04:42 后队列卡死，真因是 **Docker Desktop 自己退了**（容器全 `Exited (255)`），后端报 `Can't connect to MySQL server`。
旧的 `scripts/_watch_queue.sh` **发现不了**：它用 `mysql ... 2>/dev/null` 读队列，MySQL 没了就返回空字符串，而空字符串看起来跟「本轮没变化」一模一样 —— 于是静默空转 3 小时。

★ **吞掉 stderr 的健康探针等于没有探针。** 这是我第 3 次在同一个坑上浪费时间。

### 探针设计
四层，逐层向上：
1. `docker info` —— 引擎本身（不只容器）
2. `mysql -e "select 1"` 且 `grep -qx 1` —— 真查一次，不看 `docker inspect`
3. `curl /health` 精确等于 `200`
4. 队列计数；空值视为「读失败」而非「无任务」

任一失败 → 对应 `RECOVER` 动作：起 Docker Desktop → `docker start`/`restart` MySQL → 清代理 json + 重启后端 → `queue/start`。
「pending>0 且 running=0 连续 3 轮」判定为调度器楔死，推一把。

### 实测验证（4/4 全过）
故意 `docker stop` MySQL 后跑：
```
[13:03:49] deadline: 2026-11-10 07:00      ← 跨天正确
[13:03:52] RECOVER: backend not answering; restarting it
[13:03:58] RECOVER: backend is back
[13:04:32] WARN: 17 pending with nothing running for 3 polls
[13:04:32] RECOVER: queue start -> {"state":"started"}
[13:04:49] queue: solved=68 pending=16 running=1   ← 队列被推活
```
MySQL 从 stopped → `Running=true` 自动恢复。

### ★ 两个 Git Bash 坑
1. `--until` 必须用 **epoch 截止时间**，不能比 `HH:MM` 字符串 —— 23:00 起跑 `--until 06:30` 会在第一轮就退出。
2. `setsid` 在 Git Bash 下不起作用，进程会被回收；必须用工具的后台任务机制。

### 注意
`pkill -f watch_unattended_run` 会连带杀掉同进程组的后端 —— 停测试看门狗时踩到一次，后端 health 变 000，需重启。

**日志里没有任何 RECOVER/FAIL/exit 行** —— 这是区分「外部被杀」和「脚本自己退出」的判据。宿主回收后台进程，无解。

结果是每次被杀后队列停摆到人工发现：00:30 死，00:55 我才发现，白丢 25 分钟。

### 改法：`--once` 跑单轮就退出
抽出 `run_cycle()`，返回码 0=健康 / 1=修不好 / 2=队列排空。
`--once` 只跑一次；长驻模式变成 `while: run_cycle; sleep`。
**楔死判定需要跨调用记忆**，所以 idle 计数落到 `.probe/watchdog.idle` 状态文件——三次独立调用照样累积成「3 cycles 楔死」。

### 实测（两次都过）
```
--once 单轮:        queue: solved=72 pending=33 running=0  rc=0
连续 3 次 --once:   idle=1 -> idle=2 -> idle=0
                    WARN: 33 pending with nothing running for 3 cycles
                    RECOVER: queue start -> {"state":"started"}
40 秒后:            Running; 1 item in flight for 50s, 32 challenge(s) waiting
```
**队列被三次短命调用拉活了。**

### 现在的跑法
`for i in 1..100; do watch --once; sleep 240; done` —— 即使被杀，重启代价只是一个短命令，不像长驻进程那样丢整段历史（idle 计数在文件里）。

★ 通用教训：**无人值守场景下，状态要落盘，进程要短命。** 长驻进程在宿主眼里是可回收资源，它承载的记忆会一起消失。
